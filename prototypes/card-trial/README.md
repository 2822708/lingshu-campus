# 课后演练：独立卡牌战斗试作

《灵枢录》的独立玩法试作。主游戏不导入此页面；角色档案由用户选文件导入，只形成演练快照。2026-10-27 正式副本已通过共享底层接入主游戏，见[正式接入报告](../../doc/卡牌副本正式接入报告-2026-10-27.md)。本页面继续独立保存与构建，保留三场试炼和自身规则。

## 开始试玩

在仓库根目录运行 `npm run dev:cards`，访问 <http://127.0.0.1:3046/>。不需要账号、后端或模型 API。

- 打开“编辑简历”，先把课程与支持装备加入牌库，再到“挑选简历”勾选出发的牌。
- 出发简历选择 8–16 张，至少一张进攻牌；基础八张仍在牌库，可选择不同组合。战后奖励可继续加入本次简历。
- 默认提供同学阶示例角色。更换角色或导入主游戏设置中导出的 JSON，重新挑选来源；只支持档案中已学课程、已拥有且符合白名单的装备。
- 保存配置只影响以后开局；当前试炼保留自己的角色与简历快照。已有试炼需要确认新开才采用新简历。

专项检查 `npm run test:cards`；独立构建 `npm run build:cards`。产物在本目录的 `dist/`，不进入主游戏构建。构建预览可运行 `npx vite preview --config prototypes/card-trial/vite.config.ts`，默认端口 3047。

## 手中的牌

每回合恢复 3 点专注，尝试抽 4 张。没有使用的手牌跨回合保留，抽牌堆不足会重洗弃牌，所有牌都在手中或暂存时只抽实际可用的数量。

十张是**结束回合时的保留上限**。本回合抽牌后可以暂时超过十张。点击结束时若超限，先自行点选弃到十张；确认后对手才行动，再进入下一回合抽牌。可以返回出牌，未确认的点选不会推进现场。刷新会恢复待弃牌阶段，点选需要重新选择。

例如：4 张保留后抽成 8 张，再抽成 12 张；结束时选弃 2 张，保留 10 张后，下回合可以抽成 14 张。

防护抵挡敌人损耗后清空；敌人固守的防护留给玩家应对。进攻总量、真实损耗、来袭、预计损失、抽弃牌区数量均可见。连续三场，前两场胜利后三选一或跳过，进下一场恢复最多 6 点精力；第三场完成即通关。每场上限 18 回合，无出牌倒计时。

纸偶出手、受击、防护、破防、恢复、抽牌和最后一击只展示成功保存的结果。减少动态效果设置保留数值与文字。主要操作处于窗口内，手牌与三张奖励牌同时摆出，不再横向滚动。始终保留单行，空间充足时平铺、牌多或窄屏时横向错叠；牌宽保持约 192px（桌面）/168px（窄屏），不随手牌数量缩小字号。鼠标悬停或键盘聚焦时，单张牌略微放大并置顶，完整显示说明与实际效果；暂时不能打出的牌也可查看。低矮窗口使用简短牌面，展开后仍保留完整文字。长记录和准备台独立滚动。

## 角色、课程与装备

- 17 门现有课程映射为 6 类来源牌型，保留实际课程名与业务 ID。已学课都能加入牌库，未获得的课不会因随机奖励出现。
- 当前支持四种装备：入门薄膜键盘、军训迷彩服、降噪耳塞、运动护腕。导入时校验名称、类型、可装备标记和正数量，保留库存 ID；不要求已穿戴。
- 部分来源牌依赖攻击、防御、思维、体能或手速。加成按相对同学阶同层级基准计算，取整并封顶；牌面显示实际属性加成和结算预览。主游戏已有课程、装备加成不会重复累加。
- 三场对手依次使用同学阶同层级的弱敌、普通、强敌。复用主游戏纯敌人生成基准，将攻、防、精力按固定单位折算为卡牌数值；不随装备膨胀追涨。原值与换算单位可在简历档案中查看。
- 尚未导入角色的旧试炼继续原固定对手，记录不被自动重写。新开即可采用角色简历和同阶对手。

## 模块边界

模板与基础类型、随机/洗抽/弃牌/单牌结算、手牌几何及纸偶展示已提取到 `features/card-battle/`；本目录的对应文件保留兼容导出或只管理试炼特有逻辑。正式副本的主角色数值适配、单场规则与主存档由其独立宿主负责。

| 文件                                            | 职责                                          |
| ----------------------------------------------- | --------------------------------------------- |
| `types.ts`                                      | 独立状态、来源、简历、角色快照和命令协议      |
| `catalog.ts`                                    | 12 个基础牌型、10 个来源模板和敌人行动节奏    |
| `loadout.ts`                                    | 严格导入、来源映射、牌库/简历校验及配置持久化 |
| `progression.ts`                                | 同阶属性折算、牌效加成、主游戏敌人基准适配    |
| `engine.ts`                                     | 纯状态转移、保留手牌、待弃牌、选牌和终局      |
| `persistence.ts`                                | 独立战斗存档校验、旧快照冲突和失败重试        |
| `LoadoutWorkshop.tsx`、`loadout.css`            | 角色来源、入库、简历选择及手动弃牌样式        |
| `CardTrialApp.tsx`                              | 保存后展示、手牌选择、准备台及结果界面        |
| `HandLayout.tsx`、`handGeometry.ts`、`hand.css` | 全量摊牌/错叠、可用区域测量、放大边界与层级   |
| `motion.ts`、`BattleActor.tsx`、`motion.css`    | 实际动作反馈和原创纸偶                        |
| `style.css`、`tabletop.css`、`viewport.css`     | 基础纸本样式、牌桌布局与窗口高度适配          |
| `index.html`、`main.tsx`、`vite.config.ts`      | 独立入口和构建，不加载主游戏服务或环境文件    |

战斗仍使用独立键 `lingshu-card-trial-v1`，简历配置使用 `lingshu-card-loadout-v1`。不读取或写入主游戏存储键。新代码兼容没有角色快照的旧试炼；旧客户端不保证能读取新增来源牌和待弃牌阶段。

所有战斗命令先保存完整快照，再公布效果。失败保留现场，可重试；损坏记录保留原文，不自动覆盖。指令带试炼 ID 与递增序号，重复或非法命令不推进状态和随机数。单页旧快照检查不能代替跨标签原子互斥，请只保留一个试炼标签页。
