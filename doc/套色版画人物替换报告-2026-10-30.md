# 套色版画人物替换报告

日期：2026-10-30。状态：本地替换与验证完成；本报告本身不代表生产站点已经更新。

## 已替换

用户选择C套色版画并明确要求“替换”后，已将共享战斗人物由原全身SVG线稿换为三张独立透明立绘：主角、追问辩手、论证守门人。采用墨绿/赭红、纸白留形与半身构图，人物朝向战场内侧；实际尺寸下脸部和姿态比原细小全身图更清楚。窄矮窗口改用面部裁切，避免将整个人继续缩小。

`BattleActor.tsx` 仅选择素材并呈现已有动作信号，仍不参与存档或战斗结算。原SVG人物已移除。图片边缘透明、下缘轻微淡出，与纸色页面融合；人物与血条继续上下排列。卡牌仍保持**高:宽4:3**、单行及原悬停规则。

六种敌人暂时共用两类对手形象，属于第一批三张素材接入，不是六套独立敌人原画：

| 场景/类型                        | 使用素材                              |
| -------------------------------- | ------------------------------------- |
| 玩家                             | 主角                                  |
| 追问辩手、抢答快手、干扰考官     | 辩手                                  |
| 论证守门人、反问评审、漏洞聚合体 | 守门人                                |
| 旧现场无archetype                | 按原variant选择守门人或辩手，保留兼容 |

正式卡牌副本和旧独立试作共用组件，两处都已显示新人物；独立试作自身的旧卡牌形状和布局未被这次人物替换改写。

## 素材与加载

三张透明PNG由内置 `image_gen` 依据已选C稿分别制作。原始 PNG 保留为本地制作记录，游戏使用 `features/card-battle/ui/assets/print-{player,duelist,sentinel}.webp`。

WebP为PNG的无损格式导出，逐像素比较确认透明度与可见像素一致，没有调整图像内容或尺寸。三张素材由约8.22MB降到约5.60MB，体积减少约31.8%。仍是高分辨率原画，后续如需进一步缩减体积，可另做显示尺寸版本并重新检验观感。

通过静态 `new URL(..., import.meta.url)` 让Vite为正式页和独立入口打包带哈希的资源，支持部署base路径；未引入外部图片服务。图片不会写入玩家存档。原PNG与风格参考图不作为生产图片引用。

素材 SHA256 清单和最终提示词保留为本地制作记录。

## 动作与真实反馈

保留原有出招、受击、防护、恢复、抽牌、破势和胜负反馈。出手作用在内层人物，受击作用在外层图片容器，避免两种动作互相覆盖；浮字保持独立。尊重减少动态效果设置。

实际出“转守为攻”时，敌人精力30→24、玩家140→139，同时呈现敌方−6和己方−1。CSS出招与受击均作用于新人物图层。没有把换人物当作修改伤害、规则或存档协议。

## 验证结果

- **430/430全仓回归通过**。新增一项角色分派与图像渲染检查，覆盖六类敌人、旧variant、装饰图像及保留反馈。
- TypeScript、修改组件ESLint、修改文件格式检查通过。
- 正式游戏和独立试作构建通过，两套产物都包含三张带哈希的WebP。正式主包为 `index-CLmAsVeg.js`，独立主包为 `index-CqnN9NqQ.js`。
- 浏览器实测1280×720、1024×600、390×720、320×568、320×480，图片均成功加载；人物在血条上方，没有挤占手牌或底部操作区。
- 320×480待弃12张牌时，敌人内容下缘177.45px、手牌从209px开始，底部操作区下缘480px。
- 320×480保存失败提示高32px，敌人内容下缘183.29px，错误从197px开始，图片仍正常显示，底部按钮完整可见。
- 在独立试作实际读取现有测试现场，主角和辩手均加载新的WebP。

使用独立3048测试存档，未操作用户原试玩记录。临时验收入口、服务及视口设置已清理。构建中仍有浏览器数据较旧及正式入口较大的原有提示，不影响产物生成。

本轮未进行公网部署。上一轮UI审计中的多手牌常态遮挡、所有窗口的视觉重点及内部留白等问题，不因换人物而视为全部解决。

正式桌面与窄屏的截图保留为本地验收记录。
