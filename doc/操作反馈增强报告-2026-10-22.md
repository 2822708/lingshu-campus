# 操作反馈增强报告

日期：2026 年 10 月 22 日。回应玩家“出招、受伤、奖励和选项后果不明显”的反馈。本轮集中增强已保存结果的呈现，保持纸本校园风和现有轻量玩法。

## 本次变化

| 场景             | 玩家现在能看到的反馈                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| 每次出招         | 操作栏旁保留最新一轮的动作、对手当轮意图、实际造成与承受的损耗                         |
| 防守、破势、暴击 | 直接列出实际减免与暴击；破势成功和未固守时的低输出分别说明                             |
| 精力变化         | 双方精力条短暂过渡，并注明本轮损失；没有受伤时明确显示未受损耗                         |
| 最后一击         | 进入结果页后继续显示最后一次行动，先解释怎么结束，再展示奖励                           |
| 胜负结算         | 精力、绩点、学分、掉落等原有实际变化用独立条目突出，附实际完成轮数和累计防守减免       |
| 回合历史         | 可展开全部已记录行动，终局及刷新续接后仍能查看；撤离记录计为行动，不计作完整战斗轮     |
| 机缘选择         | 选前展示已有后续线索，选后回显所选路线；战斗路线标注“胜利后续”，避免将未完成当作已解锁 |
| 确认与出招音效   | 复用原音效开关和音量设置，操作成功保存后才触发；失败、重复提交和刷新不播放成功反馈     |

最新一轮放在固定操作区，避免窄屏玩家出招后必须向上寻找结果。详细记录默认折叠，三个主动作和一轮自动应对保持原样。终局当前行动不再提示后续冷却；历史记录仍保留当时的原始反馈。

## 实现边界

新增 `components/InteractiveBattleFeedback.tsx`，只读取已有 `battle.rounds`、`entries.damage`、`preventedDamage` 和 `crit`。它不预测伤害、不重算战斗、不发奖、不写档，也不请求模型。`InteractiveEncounterModal` 组合固定反馈、精力变化、选项后续和终局记录；`App` 仅在 `commitInteractive` 成功后触发音效。

伤害、防御、冷却、掉落预算、奖励、费用和结算规则未调整；存档版本、业务 ID 及既有兼容方式不变。没有新增连招、战斗道具、室友战斗支援或长项目，任务三仍暂缓。既有数值审计的其他问题不在本轮修复范围。

新增记录入口使用原生 `details/summary`，已纳入弹窗 Tab/Shift+Tab 焦点循环。短过渡与按钮按下效果服从现有减少动态效果设置。

## 验证结果

- 244 项自动检查全部通过，0 失败、0 跳过，比前版新增 11 项。
- 新增 8 项真实战斗内核与 React 服务端渲染检查，覆盖防守、固守、破势、暴击、致胜/致败最后轮、撤离和空记录。
- 新增 3 项受控 App 与服务端渲染检查，覆盖选项后续、实际结算、操作栏反馈、最后一击、刷新保留，以及保存失败/重复提交/静音时不误播音效。
- TypeScript 和零警告 ESLint 通过。
- 标准 `npm run build` 本轮成功。主包约 527.96 kB，gzip 171.92 kB，仍有超过 500 kB 的体积提示。前版的 Windows `realpath EPERM` 是历史结果，本轮未复现；未为此修改项目 Vite 配置。

本轮在本地 `http://127.0.0.1:3045/` 的应用内浏览器实际新建独立测试档案，在约 320 px 宽视口完成：首次机缘预告 → 进入挑战 → 防守 → 多轮稳攻 → 对固守使用破势并暴击结束 → 查看最后一击、奖励和后续线索。现场实际显示防守承受 1 点、减免 1 点；终局显示第 5 轮破势造成剩余 6 点损耗、对手未出手，精力 100 → 93、绩点 +24、学分 +8。

完整刷新并点击继续后，恢复了同一战斗、第 1 轮防守及其历史反馈。键盘验证了记录入口可以 Tab 到达、Shift+Tab 环绕到末个操作、Tab 返回记录并用 Enter 展开。这是本地窄屏浏览器检查，不代表真实手机、所有浏览器、所有战斗入口或多标签锁的完整验收。音效的触发顺序和开关经过受控检查，未单独作设备听感验收。本轮不包含真实 AI 服务商和线上部署验收。
