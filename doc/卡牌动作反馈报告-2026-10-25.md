# 卡牌动作反馈与纸桌布局报告

日期：2026 年 10 月 25 日。本轮根据“攻击、受击添加简易动画，把反应落实到反馈，界面过于规整”的反馈，改进独立模块《课后演练》。功能仅在 `prototypes/card-trial/` 内生效。

## 操作后的表现

| 实际事件         | 展示反馈                                         |
| ---------------- | ------------------------------------------------ |
| 打出进攻牌       | 卡名便签向交手区飞出，纸偶向前出手、笔划挥击     |
| 命中             | 目标短暂后退晃动，浮字显示实际精力损耗           |
| 防护与挡伤       | 护盾短暂出现，分别显示本次获得的防护和实际抵消量 |
| 完全挡住         | 显示挡住的数值，不出现受伤浮字与受击动作         |
| 破防             | 防护碎片与清除量，和精力损耗分别显示             |
| 恢复、抽牌、蓄势 | 实际恢复值、实际入手数量与蓄势提示               |
| 最后一击         | 保留进攻、命中与实际损耗，同时呈现对手落败       |
| 对手调整         | 不播放虚假的进攻或受伤；正常显示下一轮抽牌       |

动画最长约 570 毫秒，没有持续闪烁或等待动画结束才能操作的锁定。快速连续操作会替换上一个瞬时动作，完整结果仍保留在演练记录中。系统启用“减少动态效果”时，取消位移、挥击、护盾闪现和飞牌，保留数值与文字。

## 布局调整

取消牌桌整块外框与双方状态之间的硬分隔。玩家纸偶与三种对手纸偶处在有错位留白的交手区，敌人意图呈现为旁侧批注，最近反馈贴近手牌。路线标签、手牌及结束回合便签有轻微角度与高低变化，手牌悬停或键盘聚焦时抬起并摆正。

窄屏继续并排呈现双方，缩小纸偶与间距；手牌为两列，保留便捷状态条与结束回合按钮。上述响应式样式已实现，但本轮未完成真实浏览器的视觉检查，不能据此承诺所有尺寸均无重叠。

## 实现边界

- `motion.ts`：从前后真实状态及已接受命令派生展示信号，不结算规则、不读随机数、不保存动画字段。
- `BattleActor.tsx`、`motion.css`：原创 SVG 纸偶与一次性动作；按指令序号更换动作节点，不使用定时器。
- `tabletop.css`：独立布局层，按基础样式、布局层、动作层的顺序加载。
- `CardTrialApp.tsx`：完整快照保存成功后才触发反馈。失败保留现场；重试成功后才播放。重新加载、重新读取或重开不回放历史攻击。

本轮没有修改卡牌数据、战斗引擎、存档协议或随机序列，未改主游戏入口、战斗及角色存档。代码保留为本地改动，没有新增 Git 提交、上传 GitHub、发布或通知部署对话。

## 本地体验

在仓库根目录运行 `npm run dev:cards`，再访问 <http://127.0.0.1:3046/>。规则和独立存档说明见[模块说明](../prototypes/card-trial/README.md)。建议先连续打出一张防护和一张进攻，再结束回合，对照纸偶动作、精力和最近反馈；之后比较完全挡住、部分受伤和破防三种情况。
