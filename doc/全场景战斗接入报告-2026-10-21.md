# 全场景战斗接入报告

日期：2026 年 10 月 21 日。范围：把游戏中全部实际战斗入口接入同一套逐轮操作，保留纸本界面和三个主要动作。任务三的战斗道具、室友支援和长项目继续搁置。

## 1. 当前覆盖范围

| 入口                             | 当前行为                                                 |
| -------------------------------- | -------------------------------------------------------- |
| 六个预置机缘中的旧装置、公开练习 | 继续使用稳攻、防守、破势、撤离与自动应对一轮             |
| 普通期末冲刺随机战斗             | 遇敌后保存未结算现场，玩家下指令才推进回合               |
| 幸运事件战斗                     | 使用同一内核，保留幸运场景的对手与奖励差异               |
| 原有强制战斗奇遇                 | 使用配置中的对手名和风险，胜利才发战斗奇遇奖励           |
| 静态及随机生成的副本             | 四种风险均进入同一操作界面；保留准入学阶、费用和专属掉落 |
| 普通事件触发的延迟随机副本       | 回到统一冒险入口，取消旧的隐藏额外结算路径               |
| 社团 hunt 类任务                 | 从直接领奖改为挑战，胜利才发任务贡献、绩点、学分和物品   |

商店、普通剧情、幸运事件的非战斗分支继续运行。没有抽中战斗的副本仍可获得普通探索结果，没有把所有探索都强制变成战斗。社团捐赠、收集等四类普通任务保持原流程；“一键完成普通任务”会跳过需要亲自应对的挑战。

当前 App、views 和已接入的 features 中不再调用 `resolveBattleEncounter`。旧自动结算服务和回放组件保留作兼容与历史回归，不作为游戏战斗的活跃入口。

## 2. 玩家操作与规则

所有场景共用 `features/interactive/battle.ts`：先公布对手意图，再选择稳攻、防守或破势；也可撤离或自动应对一轮。强攻后有调整窗口，破势使用后须间隔两个其他行动轮，最多十二个完整决策轮。未结束前不会提前确定胜负或把奖励写入角色。

自动期末冲刺和自动自习在遇敌时停止，不替玩家出招。待处理战斗会冻结被动恢复、升学、换装、用药等外部成长；确认结果后仍须手动恢复自动操作。

普通、幸运和副本战斗沿用各自的胜利奖励、失败扣分与掉落预算；撤离和僵持保留已发生的伤耗及入场成本，不发战斗胜奖、不追加战败扣分。普通战斗同场遇到的独立非战斗机缘按原规则单列结算，界面会明确说明它与胜利奖的区别。

社团挑战只发任务配置的总奖励，不再叠加普通战斗奖和随机课程/天赋发现。入场时一次支付费用、交付材料并占用一次对应类型的任务次数；失败或撤离不退还。限额仍为原处理函数中的 20 / 10 / 5 / 3，没有提高配额；修正了旧界面显示与处理函数限额不同的问题。

战斗中显示固定的胜利绩点、学分及贡献预算、可用余额范围内的战败损失、已支付的入场费和风险。最终反馈来自实际差额，精力归零时将既有延毕降级与终局结果合并保存一次。

## 3. 数值适配与保留边界

新场景沿用互动战斗按学阶基础生成对手的方式，不让敌人随玩家换装而同步膨胀。风险、强弱分布及高阶玩家对低阶副本的压制关系仍生效。

迁移时发现旧自动战斗在线性敌人表上使用“副本最低学阶加一”，直接套用新的指数成长表后，会使低风险副本普遍必败。因此新副本的实际对手学阶与基础数值统一使用准入学阶；随机副本没有明确准入时使用当前学阶，再由风险和强度决定难度。旧自动服务的计算和随机调用顺序保留不变，历史固定种子回归继续通过。

七个学阶、1 / 9 两种层级、每档四十个分散种子的 560 场低风险基础角色模拟全部可完成，平均 4.4—4.6 轮。这证明已修复明显的跨阶错误，不代表高风险、所有装备组合或整个经济系统已经完成平衡。原数值审计的其他问题、升级加成及高阶收益曲线没有在本轮整体重做。

## 4. 保存、费用与重复操作

`begin-battle` 在同一份存档中保存对手、奖池、随机状态、父行动序号、已付费用与待处理现场；角色在成功入场前不扣费、不减战损、不领胜奖。每次合法指令先保存再展示，写盘失败时保留上一轮，重试不会重抽或重复推进。

终局通过同一父行动统一更新角色、物品、日志、结算水位和结果，重复出招、重复确认或刷新都不会再次发奖。物品实例 ID 绑定父行动，两个战斗即使随机种子相同也不会产生相同的装备 ID。

全局行动序号与六机缘的 `encounterCursor` 分离，打普通战斗或副本不会跳过预置机缘，也不会消耗首次机缘保证。旧存档没有 cursor 或战斗计划时仍能按原机缘现场继续。

非战斗副本先持久保存一次入场费再走原普通事件结算；该流程不构成对全部非战斗业务的完整事务改造。准入学阶在随机选择战斗前就统一检查，避免非战斗路径绕过资格。

## 5. 主要模块

| 文件                                       | 职责                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| `features/interactive/adventureBattle.ts`  | 同步固定各场景对手与奖池、费用及材料交付、社团次数、纯终局结算、计划校验 |
| `features/interactive/state.ts`            | 统一父行动、直接战斗入口、机缘游标、一次结算与延毕                       |
| `hooks/useGameState.ts`                    | 完整快照先落盘、关键费用提交、最新玩家及待处理门禁                       |
| `views/adventure/useAdventureHandlers.ts`  | 普通、幸运、强制战斗奇遇、副本与随机副本入口                             |
| `views/realm/useRealmHandlers.ts`          | 准入与余额检查、同次点击防重、费用交给统一保存                           |
| `views/sect/useSectHandlers.ts`            | 社团挑战与普通交付分流                                                   |
| `components/InteractiveEncounterModal.tsx` | 所有场景共用的意图、费用、指令与结果界面                                 |

AI 不参与伤害、意图、胜负、费用或奖池计算；战斗中也没有逐轮模型等待。本轮没有扩展新的 AI 技能或室友战斗能力。
