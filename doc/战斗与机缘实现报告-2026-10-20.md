# 战斗与机缘实现报告

日期：2026 年 10 月 20 日。范围：先打通互动流程，再补齐首版内容；道具、室友战斗支援与长项目暂缓。本文记录当前代码，与[原规划提案](战斗参与与机缘分支规划-2026-10-18.md)并列保留。

## 1. 已接通的玩家流程

“期末冲刺”主按钮首次必定引出互动机缘，此后以 35% 概率穿插出现，进入一条完整的本地流程：

> 固定本次机缘与选项 → 玩家选择 → 直接反馈或进入逐轮战斗 → 一次终局结算 → 记入档案并继续。

开始机缘时不会预发奖励或提前确定战斗胜负。挑战选项创建同一父行动下的战斗现场，玩家每次指令才推进一轮；完成后才把精力变化、胜利奖励、后续事实与手记一起保存。每次合法选择和指令先保存成功，再更新界面；保存失败时保留上一现场并提示错误。

互动机缘在六类内容间轮换，离开也消费本次机会；其余行动保留原来的商店、幸运事件、普通战斗与掉落渠道。抽中互动入口但保存失败时停止本次行动，不再转入旧流程结算另一份奖励。副本与普通随机战斗仍沿用既有计算与战斗回放，尚未迁入互动内核。不能据此认为所有战斗都已改成手动。

## 2. 首版内容与反馈

| 机缘             | 首次可选路径                 | 已接入的后续反馈                                                               |
| ---------------- | ---------------------------- | ------------------------------------------------------------------------------ |
| 研习室的旧装置   | 排查、挑战核心、合作、离开   | 排查解锁按笔记复测；合作解锁分工复测；挑战胜利解锁进阶联调，未完成保留现场线索 |
| 晚自习的空白草稿 | 独立梳理、合作、离开         | 自己的笔记用于下次讲解；合作后可以核对两份解法                                 |
| 书页间的检索卡   | 整理索引、归架勤工、离开     | 索引降低下次检索精力费用；归架记录出现在后续场景                               |
| 社团展板的空角   | 补写说明、整理印件、离开     | 下次沿用说明稿；印件整理留下页序标签反馈                                       |
| 器材室的送还单   | 送还并记路线、核对登记、离开 | 下次沿熟悉路线少耗精力；保留检查登记事实                                       |
| 公开练习的邀请   | 旁观、上场挑战、离开         | 旁观笔记提供后续意图提示；胜利开放进阶练习                                     |

合计四个非战斗主导机缘、两个可选择挑战的机缘，不另加任务面板、新货币或技能树。费用、收益和可用性在选择前展示，提交时重新检查资源，不能预借本次奖励支付费用。离开不扣选项费用、不领奖励，但结束这次机会。

费用和奖励在创建现场时按学阶基础与层级缩放：精力按基础精力、绩点按基础升学需求、学分按学阶温和增长；不跟随装备、当前精力或当前绩点上限。大一一层仍采用原提案的试作值，如排查精力 −6、绩点 +10，核心挑战胜利总绩点 +24、学分 +8。这些是首版初值，尚不代表完整经济平衡已验收。

合作只绑定玩家已有的室友，最多增加实际可用的默契空间；没有室友时明确改为同学协作，不创建新角色。这是事件分工反馈，未把室友攻击、技能或战力接入战斗。

## 3. 战斗保持三个主要动作

| 动作 | 当前规则                                                                             |
| ---- | ------------------------------------------------------------------------------------ |
| 稳攻 | 沿用原伤害与暴击的基础公式，稳定输出                                                 |
| 防守 | 本轮不输出，基础伤害、暴击和意图倍率计算后将实际来袭减半；慢速角色同样先获得防守     |
| 破势 | 清除固守并正常攻击；目标无固守时仅发挥七成五输出，使用后须完成两个其他行动轮才能再用 |

另有撤离与“自动应对一轮”。自动按钮只为当前这一轮选择一个动作，使用与玩家相同的内核，不代表全程托管。

对手有强攻、固守、调整三种已公布意图，以及偏强攻、偏固守、均衡三种行为。强攻后的下一轮固定为调整，提供容易理解的进攻窗口。意图在玩家提交前锁定，不会根据尚未提交的选择临时换招。固守最多持续两个决策轮，可以被破势清除。

每轮双方各至多出手一次，手速决定先后；先被击败的一方不反击。战斗最多十二个完整决策轮，分别以胜利、力竭、主动撤离或僵持撤离结束。未胜利不发胜利收益，不额外追加该机缘的战败扣分；精力为零时将既有延毕降级、清绩点与恢复精力合并进同一次终局保存。

新对手按学阶基础与层级生成，避免中后期仍使用低阶线性数值而被基础角色一击结束；不随玩家装备数值同步膨胀。节奏仍受角色成长、装备与策略影响，不能保证每场都固定在同一轮数结束。

## 4. 本轮采用的简化边界

- 从待选机缘到战斗、结果确认，整个待处理流程暂停自动自习、自动期末、自动升学、被动回血及外部角色/日志写入；自动操作不会在结束后自行恢复。
- 待选期间也不允许打开背包补给。资源不足时可选择离开，处理完结果后再补给；这是相对原提案“待选可补给”的简化。
- 当前机缘面板没有收起或关闭入口。刷新后通过继续游戏回到已保存的同一选项、对手、轮次与随机状态，不会重抽现场。
- 没有全程托管、战斗道具、室友战斗协作、实时操作、多队伍或逐回合模型请求。任务三与三阶段长项目继续搁置。

## 5. 存档与重复提交

存档继续使用既有 `SAVE_VERSION = 2` 和原存档 key，新增可选的 `interactive` 扩展，其内部版本为 `1`。扩展保存行动序号、结算水位、已完成事实、待处理选项、战斗现场、指令序号与固定随机状态；玩家、日志和扩展同属一次保存。旧档没有扩展时从空进度开始，不补发历史奖励；损坏扩展拒绝加载或导入，不静默删除待处理现场。

父行动 ID、阶段检查、指令序号与结算水位共同阻止同一流程内的重复选择、重复战斗指令和迟到确认再次发奖。终局保留结果，直到玩家确认归档；确认后才允许下一次机缘。

`Web Locks` 用于同一存档的单标签页写者。互动入口需要支持此能力的现代浏览器，并使用 localhost 或 HTTPS 环境；另一个页面持有存档锁时不能继续写入。不支持该能力时互动入口会给出错误，不宣称支持所有浏览器、普通 HTTP 部署或跨设备同步。旧客户端可能丢弃新扩展，不能保证降级使用后仍可继续当前现场。

## 6. AI 与原系统边界

六个机缘、选项、反馈与战斗意图均来自本地预置内容和程序规则，关闭 AI 也能完整运行。这一轮交付的是互动玩法与持久化流程，没有新增模型生成剧情、战后 AI 回顾、`choice-event` 等 AI 技能或人物长期记忆。已有三协议接入、三项文案技能与配置能力仍见[AI 实现报告](ai/初步实现报告-2026-10-16.md)。

原[数值审计的 31 项问题](数值审计报告-2026-10-15.md)没有在本轮整体解决；尤其不能把事件默契反馈视为室友战力已生效。副本旧回放、排行榜、UID 后端与真实服务商能力仍需各自验证。
