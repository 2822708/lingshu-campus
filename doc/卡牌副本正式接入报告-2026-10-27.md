# 卡牌副本正式接入报告

日期：2026-10-27。状态：已在本地项目实装，尚未提交、上传或部署。

项目为 `lingshu-campus`。

## 实际入口与玩法

主界面进入“考研副本”，仍显示六个随机去处。可以先整理简历，再按地点报名；课程和装备不作为必须准备的门槛，默认八张基础牌即可使用。入场根据当前角色重新校验学阶、精力不少于三成、学分、冷却、行动锁、报价批次和简历修订。

发生战斗时使用单场卡牌：3点专注，每回合抽4张，未出手牌保留，结束时超过10张先选择弃到10张；可以取消弃牌返回出牌，弃牌确认前敌人不行动。最多12回合，胜负、撤离与僵持沿用原结算原则。所有手牌单行重叠，维持192px桌面牌宽、168px窄屏牌宽；鼠标悬停或键盘聚焦展开到最上层，禁用牌同样可以查看。

普通冒险、社团挑战和存档中已开始的逐轮战斗继续原有操作。独立试作仍保留三场结构与独立存档，不把试玩角色、进度和奖励迁入主游戏。本轮没有增加地图、遗物、职业树、新货币或室友战斗支援。

## 与主游戏的联系

- **角色**：直接读取当前精力和最终属性，没有满血重开或试玩单位换算。战斗恢复只能恢复本场损耗，最高到入场精力；发现课程后的加精力与力竭后的延毕恢复仍由原父结算处理。
- **课程**：每门已学课程提供一个有稳定来源ID的牌实例，映射到六类模板；未携带课程牌不会取消其原有被动属性。
- **装备**：四类白名单装备只有实际装备后才提供来源牌，同一真实物品不重复复制；已进入角色最终属性的装备加成不会再加一次。旧物品没有统一模板ID，白名单同时核对名称、类型与槽位，来源实例仍采用原背包ID。
- **简历**：先收录进牌库，再选择8–16张，至少包含一张进攻牌。卸下或失去来源后阻止新入场，需明确整理；进行中的卡战已冻结牌面，不被后续目录修改重算。
- **敌人与战果**：读取原 `createAdventureBattlePlan`，不再抽另一套敌人或重复乘风险。奖励、失败损失、独立机缘、课程与天赋发现共用原结算函数。
- **探索**：大厅非战斗分支使用原本地模板与共享资源更新函数，抽奖券、室友、课程发现、物品和损耗继续生效；分流、结果、费用与水位在同一次快照中保存。普通旧事件也复用提取后的资源更新体，未整体改造其他业务。

## 模块与存档

| 模块 | 职责 |
| --- | --- |
| `features/card-battle/types/catalog/shared` | 卡牌模板、通用随机、洗抽、弃牌及效果结算 |
| `features/card-battle/engine` | 单场纯战斗指令、冻结敌意、规则与存档校验 |
| `features/card-battle/ui` | 受控牌桌、纸偶动作、单行手牌及终局反馈 |
| `features/card-dungeon/sources/loadout` | 主角色来源、牌库/简历、失效来源和修订校验 |
| `features/card-dungeon/numericAdapter` | 将最终角色与原敌人计划换成冻结的整数牌面 |
| `features/card-dungeon/exploration`、`utils/adventureResult` | 确定性探索与原资源规则的共享更新 |
| `features/interactive/state` | 唯一父行动、扣费、指令、水位、结算与一次延毕 |
| `hooks/useGameState` | 页面写入锁、完整快照先写后显示、迁移备份 |

外层 `SAVE_VERSION=2` 不变，互动扩展从1升级为2。没有扩展和旧扩展1可读入；旧未完成战斗保留原随机状态、回合和费用，继续旧引擎。迁移前将原始字节保存在 `npu-game-save:pre-card-v2`，只在没有该备份时写入。未知协议、损坏牌区、来源修订或错拼计划会拒绝加载，保留原档。

卡战每次有效指令保存完整现场后才更新内存和动画。费用、战果与结算水位同次保存，旧界面回调、重复指令、乱序指令和重复确认不能重复领取。普通自动保存关闭时，关键行动仍保存。旧匿名探索续接意图在确认时同次消费并建立后续现场，不先清空后异步补做；当前本地模板实际不会生成该标记。

## 数值校准

对七个学阶、1/5/9级、四档风险、基础和强化两种角色、12个固定种子，共完成2,016对新旧战斗比较。进攻预算采用0.35，防护预算0.2、防护基础上的恢复预算0.5。基础中风险胜率旧/新为59.9%/58.7%，平均回合9.38/9.29；原初稿0.5使新胜率达到99.2%，故未沿用。

这是默认八张基础牌的可见策略对照，不证明两种玩法完全等价，也不证明所有课程/装备构筑已经平衡。完整方法、风险分组和原始数据见[数值校准记录](卡牌副本数值校准-2026-10-27.md)。

## 验证

自动检查命令：`npm test`、`npm run test:dungeons`、`npm run test:cards`、`npm run typecheck`、`npm run lint`、`npm run build`、`npm run build:cards`。最终数量和执行结果见下方收尾记录。

自动回归覆盖真实App连接与受控Hook：大厅ID/批次校验、来源失效、简历修订、入场不补血、单次收费、保存失败不推进、刷新续接、旧档备份、0种子、牌区和计划损坏、最后一击、力竭只延毕一次、重复确认及探索续接。纯函数、组件处理器与受控Hook证据不等同于浏览器证据。

真实应用内浏览器在独立3048端口使用测试角色，未读取或操作原3046试玩存档，实际完成：

1. 主游戏继续 → 副本大厅六报价 → 查看课程来源与16张简历 → 保存返回，报价保持稳定。
2. 从大厅报名进入非战斗探索，确认精力、绩点、学分、室友和净费用反馈。
3. 卡战保留手牌4→8→12，结束进入待弃牌；刷新仍处于同一回合、同一精力和牌区，未确认的弃牌选择作为本地草稿重新选择。
4. 手选两张弃到10后才结算敌袭，下一轮再抽4至14张；课程攻击、防护抵挡与清空、专注消耗均有实际反馈。
5. 原生鼠标悬停禁用牌，完整展开并高于邻牌，未消耗专注；最后一击保留纸偶动作，胜利结果刷新后继续确认，不重复发奖。
6. 旧互动协议1的未完成现场加载后仍显示稳攻/防守/破势，并能正常撤离结算。

测试包含1280×720、1024×600、390×720与320×568窗口。窄矮屏组合曾出现人物区规则冲突，已针对实测修复；窗口覆盖不等于真实手机验收。真实多标签竞争、线上部署、后端UID/排行榜与真实模型接口未包含在本轮验证中。

界面截图及校准原始数据保存在 `outputs/卡牌副本接入-2026-10-27/`。临时浏览器测试入口在验收后移出生产入口目录，保留源码文本用于复核。
