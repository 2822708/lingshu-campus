## 关键行为变化

事件现在先通过现有本地生成器固定一次结果，再调用 AI 润色 `story`。模型只能返回文字，额外数值、物品或未知字段会被拒绝；网络和校验失败直接返回原结果，不能再次随机生成。这明确停止了旧版由模型随意决定奖励的行为，保持的是现有本地规则基线，不能解释为原有模型奖励被原样保留。

升学短句只描述已经确定的结果，对手名称只改变显示称谓。输出格式限制不能证明文字语义完全真实，因此不从文案解析数值，也不把生成内容写作人物事实记忆。长期记忆依赖后续的已提交事实账本。

请求上下文在读档、新建、删档、返回首页、卸载、导入、延毕及重新出发时取消。主要行动在等待后核对代次，旧响应和延后副本回调不能继续旧行动；配置变化取消文案请求并使用同计划本地回退。创建和继续游戏的 UID 等待也增加代次检查，避免删档后迟到请求重新写回角色。

这不是完整的全存档事务系统：分散的玩家写入口、跨标签页单写者、持久行动账本及一次性奖励提交仍按 P1 计划实施。本轮不能承诺已经解决所有重复提交或所有旧存档问题。

## 验证记录

验证使用虚构角色、假密钥、可控随机种子和模拟 fetch，不读取真实玩家存档，不调用真实模型。

- 自动化覆盖三协议、闭合 JSON 契约、非法字段与极值、超时取消、旧配置、会话与长期保存、存储异常及旧自定义代理地址。
- 多种固定种子下比较日常、机缘、副本的在线与离线结果，除文字外完全一致，随机调用次数一致。
- 对空 HTTP 200、普通“OK”和合法事件文案分别测试，前两种拒绝；测试前后配置及游戏存档不变。
- 保留旧天赋、物品、存档和本地玩法回归。旧 31 项数值缺陷仍另轨管理，不因本轮测试通过而视作已修复。

最终自动化共 **82 项通过、0 失败**，类型检查通过，ESLint 0 错误 0 警告。新增生命周期用例使用内存 Hook 依赖替身，验证迟到 UID 不复活删档、不覆盖新角色、旧读档失败不删除新档；它们不是浏览器验收。完整命令输出保存在本会话 `outputs/AI增强初步实现-2026-10-16/`。

浏览器访问 `127.0.0.1:3002` 超时，服务启动日志不能替代页面验收；该测试服务已结束。真实接口、手机布局与交互尚未完成验收。

标准 `npm run build` 在当前执行环境遇到 Windows `realpath EPERM`；使用同一 Vite 配置的临时 `resolve.preserveSymlinks=true` 覆盖可完成生产构建，未修改项目 Vite 配置。报告区分标准命令失败与覆盖构建成功，不能把环境限制写成标准构建已通过。

## 如何使用与下一步

在首页展开 AI 文案设置，选择服务商，填写自己的模型 ID 与 Key，核对目标主机，测试当前草稿，再启用并保存。默认不自动请求、不启用 AI。详见[接入说明](../../config/README.md)。

接下来先在可用浏览器和受控真实接口完成三项能力的操作验收，再推进完整快照提交、行动幂等、事件单与一条三阶段室友项目。首版内容上限保持为 6 个日常选择事件、1 条三阶段项目、8/10 叙事标签和 1 类回顾，避免扩充内容先于结算可靠性。
