# AI 增强体验与内容设计

状态：规划，尚未实现。本文的事件、剧情、事实账本、交互与验收均为拟议方案；P1、P2 表示建议顺序，不代表现有功能。所有示例数值仅用于说明选择差异，实施前须结合数值审计与实际收益校准。

## 体验目标与边界

让《灵枢录 · 校园成长记》从重复行动，逐步形成“做过什么、与谁合作、后来怎样”的个人记录。背景始终是一所虚构的工科学园，沿用纸本成长档案、手记正文和克制的墨绿强调。丰富来自行动的后续，不依赖不断增加入口、装备倍率或奖励频次。

P1 只做一个闭环，硬上限为六个日常选择事件、一条三阶段室友项目、八学部与十命格的叙事标签，以及一种阶段回顾。日常事件覆盖自习、研习室和社团，每个两至三个选择，少量配一次后续。先把这些内容做完整，再考虑数量。P2 扩充项目分支、室友关系差异和内容库，不先做自由聊天、校园地图或真实日历。

## 程序决定事件，AI 负责表达

P1 中，程序先确定事件、可选项 ID、触发条件、费用、结果和后续节点；AI 只能润色标题、场景、对白及结果说明。不得生成新选项、改变条件、决定奖励、临时创造道具或承诺未发生的关系变化。显示给玩家的费用与收益由程序插入，不能从模型文本中提取结算。新事件只替换既有非战斗行动的本次结算，不在原有收益之上再免费发一份；战斗链不插入新选择。

同一事件需要“等待选择、已结算、等待后续、完成”的明确状态。检查条件、扣费、应用结果和记录选择作为一次提交；重复点击、刷新或重试不能重复发奖。正文尚未生成也不阻塞结算，模型返回与已定事实冲突时直接使用本地文案。

项目参与者绑定室友 ID，名字只是显示信息，不发送玩家自定义姓名来换取叙事效果。若参与者已不可用，暂停该线并说明原因，不把默契奖励发给另一名室友。中止与替换参与者的叙事放到 P2。

## P1 完整示例：研习室的传感器小项目

示例室友称为“阿砚”，实际关联已获得的室友。前提是玩家已有室友，并完成三次有效行动，之后在一次可替换的非战斗行动中触发。无室友时用同学引导事件提示合作主题，不自动向 player.pets 添加角色，不发放室友默契。有效行动拟指一次已结算的自习或期末行动；冷却中点击、打开弹窗、购买和重复请求不计数，一个选择只完成被替换的那次行动，不额外制造一次推进。

当前没有游戏日历，因此阶段按有效行动数与剧情状态推进。第一阶段后再完成两次有效行动，第二阶段进入待触发；之后再完成三次，第三阶段进入待触发，均在下一次可替换行动呈现。以下表格为各次行动的完整结算示意，费用和收益均不得与普通行动重复计算。

### 第一阶段：确定怎么开始

阿砚带来一组不稳定的温度读数，你们需要为研习室做一个小型监测装置。

| 选择 | 费用与结果示意 | 留下的事实 |
| --- | --- | --- |
| 先查资料，独立列出误差来源 | 精力 −8，绩点 +12 | 你整理了问题清单 |
| 和室友一起拆看现成装置 | 精力 −5，学分 −4，绩点 +6，默契 +2 | 你们共同核对了接线 |

前者重在学习，后者节省精力并增加合作，代价是花费学分且绩点较少。后续场景会引用“问题清单”或“共同接线”，不额外赠送隐藏加成。

### 第二阶段：原型读数仍有偏差

正文依据第一阶段改写：独立查资料后，阿砚拿着清单来核验；共同拆看后，你们发现当时记录的一处接点需要复查。

| 选择 | 费用与结果示意 | 留下的事实 |
| --- | --- | --- |
| 使用常规元件，按步骤重测 | 精力 −6，学分 −6，绩点 +14，默契 +1 | 完成了一次规范复测 |
| 利用旧件，分工排查误差 | 精力 −10，绩点 +8，默契 +3 | 你们记录了旧件的限制 |

常规方案更省精力、绩点较多，却需要学分；旧件方案降低支出，增加协作，但消耗精力。P1 不调用背包中的同名材料来模糊扣费，此处“旧件”是场景描述，不凭空生成可出售物品。

### 第三阶段：决定如何收尾

两种原型都可完成项目，区别在于如何呈现成果。正文回顾已选路线，不能把旧件路线说成购买了新元件。

| 选择 | 费用与结果示意 | 留下的事实 |
| --- | --- | --- |
| 做一次公开演示 | 精力 −10，学分 +12，绩点 +18，默契 +1 | 你们演示了装置并说明局限 |
| 整理共同复盘，交给下一组 | 精力 −4，学分 +4，绩点 +10，默契 +4 | 你们留下了可复用的记录 |

公开演示偏向成果回报，复盘偏向精力保留与关系成长，没有固定适用于所有资源状态的最优解。选择“查资料→旧件排查→共同复盘”，剧情账本净变化为精力 −22、绩点 +30、学分 +4、默契 +7；推进阶段期间的普通行动另行记账。

精力费用要求扣除后至少保留 1 点，学分须足额；条件不足时展示差额，允许收起后补充资源再来。默契写入该室友的现有 affection，最高 100；溢出部分不兑换货币。完成只标记剧情结束，不再附加一份未展示的大奖。

## 学部与命格怎样进入故事

P1 用同一条项目骨架适配八学部，不给每个学部各写整条故事；仅改变观察对象、措辞和对白，不改变上述选项 ID、条件、费用或收益。

| 学部 | 叙事观察角度 |
| --- | --- |
| 电路 | 接线与测量 |
| 信号 | 噪声与读数趋势 |
| 算法 | 数据整理与验证步骤 |
| 网络 | 数据传输与访问边界 |
| 光电 | 光照变化与传感观察 |
| 物联 | 设备连接与采集记录 |
| 材料 | 接触、老化与重复测量 |
| 自控 | 反馈、稳定性与调节过程 |

命格只影响角色如何表达犹豫、合作与得失。例如卷王倾向把问题写成清单，摆子更在意能否简化流程，社恐可以用笔记参与讨论，社牛更愿意解释方案；玩家仍可选择任一路线。这里不新增数值 buff，不覆盖原有天赋效果，也不让“内向”等于不合作或某个命格永远成功。

## 事实回顾与离线一致性

P1 计划新增最小事实记录：事件与选项 ID、绑定室友、阶段、结算前后资源及结果标记。成长回顾只引用这份记录；没有记录的考试名次、科研成果、人物评价和感情变化不得补写。回顾可说“你们使用旧件完成了排查”，不能说“你拿下了全校第一”。

AI 开启时润色同一组事实，关闭、超时或输出无效时使用预写版本。全离线必须能走完同一剧情，触发、选项、结算及完成状态完全一致；在线不提供专属奖励。回顾末尾附简短事实条目，玩家能对照实际变化。P2 再做跨项目回忆，优先引用已完成事件，避免无限保存原始对白。

## 手机呈现与交付验收

P1 将待选择事件放在手记中的一条记录，点开后使用底部事件单：一段正文、两个带费用的选项及“稍后继续”。桌面沿用同样内容，不新增常驻功能区。选择完成后原地变为结果记录，后续到来时接在同一条剧情下。

自动自习或自动期末遇到选择立即暂停，并显示“等待你的决定”；关闭事件单仍保持暂停，不私自代选。完成选择后由玩家明确恢复自动模式。阅读回顾不会扣费，也不会推进剧情。

P1 验收以同一初始状态走通在线与全离线两次为准：逐阶段比较选择、费用、资源和默契；核对刷新不重复奖励、资源不足可稍后续接、手机能看清费用、自动模式确实停下，以及回顾中每句事实均有记录。P2 扩充内容前，先确认完整闭环可重复核对；本文件不代表这些能力已经交付。
