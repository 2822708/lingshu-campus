# UI 历史要求核对

> 比例更正（2026-10-29）：用户明确4:3指**高:宽＝4:3**，即**宽:高＝3:4**，应为竖牌。此前横牌尺寸及“已满足4:3”的判断源于比例理解反了，不再作为现行验收结论。随后已完成[正式页比例修正与复核](卡牌高宽比修正-2026-10-29.md)：宽192×高256、窄屏宽168×高224。下文原有尺寸、截图与测量保留为历史记录，其他UI偏差仍有效。

日期：2026-10-29。范围：用户在本对话中提出的主界面、战斗界面和卡牌交互要求。核对当前本地代码、既有截图与报告，并重新实测正式卡战；本轮不修改界面设计或游戏规则。

## 结论

初次核对时没有完全满足全部要求。单行、不滚动、人物与精力条分行等具体规则已经实现；卡牌比例此前理解反了，随后已按用户澄清后的高:宽＝4:3修正并重新复核，见顶部后续报告。内部紧凑度、多张手牌的常态辨识、视觉重点、成熟且有辨识度的画风仍有偏差。

此前把“外框铺满窗口”作为“上下不留白”的完成依据，把“每张牌有一个可见入口”作为“所有卡牌一次性显示”的完成依据，判定偏宽。人体比例变成熟只证明绘图方向调整，不能代替画风验收。

最初“暂时不改变设计”之后，用户明确选择纸本校园风并多次要求调整布局，因此当前应遵循后续明确要求；不能再用最初约束阻止界面修改。独立试作后来已经有正式模块接入；核对时优先以正式卡牌副本为准，同时披露旧试玩入口的差异。

## 与 UI 紧密相关的玩法操作约束

- 课程、部分装备和战术先进入牌库，再选入简历：准备页有“可用来源/牌库/简历”三个入口及明确加入/移出操作，装备自动特性与选入装备卡有分别说明。
- 牌威力与角色属性联系、敌人学阶与原项目一致：正式牌面有实际效果预览及属性来源，敌人信息有原学阶与新战斗类型。本轮只核对展示和入口，没有重跑数值校准。
- 每轮抽4、未出牌保留、结束时超10手动弃置：当前界面有保留手牌提示、准确的弃牌数量和确认按钮。不能因为规则保留了更多手牌，就忽略常态可读性下降的问题。
- “不要过于复杂玩法”仍有效：修正上述界面偏差不应继续增加玩法按钮、额外结算层或新的操作步骤。

## 需要明确的取舍

“单行、不滚动、维持可读牌宽、所有牌面正文无重叠同时可读”在窄屏和多手牌时无法全部成立。当前实现选择前三项，以重叠和悬停读取承担第四项。用户没有明确把“全部显示”降格为“每张有一条窄缝”，因此仍只能判为部分满足。

若继续保留前三项，下一次至少应把常态的牌名/费用辨认、依次查看和安全出牌作为验收点；若要求所有正文同时可见，则需要重新选择排布约束，不能仅通过层级或浮动放大声称已经兼得。

“人物更大”与“紧凑、重点突出”也需要一起设计。继续单独扩大立绘不能消除大窗口空白，反而可能让威胁预告失去主次；应先分配战斗区、状态与预告的位置，再确定人物的合适尺寸。

## 后续修正优先级

1. 先解决大窗口内部空白和信息重点，保留4:3、单行、主按钮可见及人物/血条分行，避免重新引入右上独立行动板和“刚刚”行。
2. 再解决多手牌常态看不清牌名/费用的问题，分别验证鼠标、键盘与触屏，不能只验证没有页面溢出。
3. 统一纸本校园的成熟绘图，增加真实角色的轮廓、姿态和服装辨识度，以实际页面效果验收，减少模板化。
4. 处理旧独立试玩与正式页的差异，明确哪个入口供继续试玩，避免用户在旧入口看到已经要求删除的布局。

这些是核对后的建议，本轮没有擅自执行新的设计取舍。

## 证据与验证边界

本轮使用独立3048端口测试存档，实际进入正式卡战，结束两轮形成12张手牌，检查1920×1080、1280×720、320×480。未操作用户原记录；验收入口与服务已清理，临时视口已恢复。

当前12张牌在320×480中，各按钮自身scrollHeight等于clientHeight，样本未发现纵向裁切；这不能证明目录全部34种牌、长装备名称、所有属性加成在所有窗口都不裁切。重叠导致的遮挡已经明确存在，与按钮自身没有溢出是两回事。

本轮未修改业务、样式或人物源文件，没有重新构建或运行全仓测试；此前通过的测试仅作为历史证据，不代替本轮的视觉判断。
